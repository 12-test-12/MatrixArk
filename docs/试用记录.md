# MatrixArk 首版试用记录

> 依据 [首版开发计划](../DEVELOPMENT_PLAN.md)。以下为待填写的试用模板。运营负责人登记实际操作和证据，项目负责人签署版本结论。

## 配对采样

一批指一篇原稿生成的一组平台版本及其目标账号。首周记录 5 批旧流程，试用时再做 5 批可比的新流程。每组对齐工作室、平台组合、目标账号数和稿件复杂度。选相近稿件分别走两种流程，每个账号仅实际发布其对应稿件。

计入每名成员用于改写、审核、排期、发布、回填和异常处理的实际分钟，汇总到批次。等待模型、平台审核、到期执行和回填的时长单列。原稿就绪、确认通过、结果回填用来追踪进度。未完成和不可配对的批次保留记录及原因。

## 版本与通道证据

| 批次 / 平台 / 账号 | 稿件及首稿来源 | 首次确认版本 | 标题、正文和话题原样确认 | 重生成或换封面 | 通道及环境 | 状态与作品证据 | 核对人及下一步 |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |

首稿直接确认须满足未重生成，且首次生成和首次确认的标题、正文、话题相同。重生成与换封面另计。样本结论注明进入审核的首稿数、直接确认数和未确认数。真实发布统计仅使用真实通道记录。

## 试用结论

- 可比且完成的对照组数
- 每对节省分钟数和中位数
- 首稿直接确认情况及返工主因
- 小红书真实交接、到期与逾期提醒、回填证据
- 官方通道真实投稿、文章 ID、状态回读证据及尚待验证项目
- 50 个账号容量记录、第 51 个账号用例和故障演练引用
- 运营负责人、项目负责人及签字日期
