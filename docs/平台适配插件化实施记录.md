# 平台适配插件化实施记录

实施日期为 2026-11-26，对应 [核心架构重构实施计划](./MatrixArk-核心架构重构实施计划.md) 的第二阶段。基线包含第一阶段交付及工作区原有业务改动。

## 平台注册与执行

`packages/adapters/src/registry.ts` 提供 `AdapterRegistry`，按平台与通道注册工厂、内容策略和成效能力。默认注册在包入口集中维护，覆盖 B 站官方专栏、两个平台的人工交接和沙箱。`TasksModule` 注入独立注册表，领取、自动投稿、回读和成效同步均通过该注册表解析适配器。

注册前检查全部平台通道是否冲突，冲突时整次注册失败。解析时检查工厂返回的通道、支持平台和成效方法是否符合声明。旧 `resolveAdapter` 入口继续代理默认注册表，`forceSandbox` 保留人工交接优先规则，试用沙箱继续使用确定的受理结果。

`ChannelAdapter` 增加可选的 `fetchMetrics` 能力。B 站沿用原成效读取实现，旧 `fetchArticleMetrics`、`validateBilibiliArticle` 和适配器类导出继续可用。

## 内容与账号策略

B 站官方专栏的分类、摘要、标题及正文校验移至独立内容策略文件，排期、执行预检和适配器复用同一校验函数。注册项同时声明视频支持和是否需要读取图片文件。原版本级 Shared 校验、人工交接字段限制和视频封面规则继续沿用原实现。

`accounts/account-capabilities.ts` 统一解析发布通道、身份核验展示、人工交接、自动通道和成效同步资格。B 站专属账号策略独立保存，账号列表、矩阵组统计和任务领取共用能力结果。旧 `publishChannel` 与账号标识辅助函数保留原路径出口。

历史仅 UID 的 B 站人工记录继续受限。扫码、Cookie 和密码托管继续用于人工交接，密码托管的身份核验展示沿用原规则。官方账号继续要求有效授权、匹配密钥与专栏权限。试用、沙箱、归档和限流条件保持原值。

## API 平台运行时

`PublishingPlatform` 描述平台凭据读取、应用配置、图片准备、候选查询条件和远端作品 ID 校验。`BilibiliPublishingPlatform` 承接原 B 站实现，由 `TasksModule` 的 `PUBLISHING_PLATFORMS` Provider 统一登记。

`TaskPlatformService` 负责通用编排，通过注入的注册表及平台运行时取得规则。B 站凭据、应用配置和图片处理已移出该服务。派发、回读和成效服务通过平台运行时组合原有筛选条件，原候选数量、调度周期、串行提交、事务和租约规则继续沿用。
