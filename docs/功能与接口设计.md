# MatrixArk 功能与接口设计 v1.3

> 依据 [项目底座 v1.1](../PROJECT_FOUNDATION.md) 及 [首版开发计划](../DEVELOPMENT_PLAN.md)。实现与数据约束见 [技术设计](./技术设计.md) 和 [数据库设计](./数据库设计.md)。

## 功能分布与权限

一个甲方使用一个工作室。同一运营通过工作室切换进入不同客户的业务。账号可以继续加入原工作室，首版按 50 个账号做容量验收，另验第 51 个账号可新增、查找和排期。

| 功能区 | 主要操作 | 发起角色 |
|---|---|---|
| 工作室设置 | 创建或切换工作室，维护成员、角色和飞书群配置。 | 已登录用户可创建和切换有权限的工作室。负责人管理成员与配置。 |
| 账号 | 新增、查找、停用账号，查看授权范围、有效期、失效与限流状态。 | 负责人、编辑管理。工作室成员查看必要状态。 |
| 原稿与平台版本 | 粘贴正文、上传图片、一稿多版、编辑平台稿、调整图片顺序与封面。 | 负责人、编辑写入。 |
| 审核 | 预览完整快照后确认或退回，退回意见产生作者待办。作者具备确认权限时可自行确认。 | 负责人、编辑、审核员确认或退回。 |
| 排期与结果 | 预览平台与账号配对，排期、调期、取消并查看逐账号结果。 | 负责人、编辑排期和管理。工作室成员查看。 |
| 交接与待核实 | 下载已审素材，复制发布包，记录已发布、失败、待核实及人工核对证据。 | 负责人、编辑、运营回填和核对。负责人核对后可取消已交接任务，或凭证据更正已取消任务。 |

粘贴正文保留段落并清理外部样式。上传接收 JPEG、PNG 和 WebP，每张最多 20 MiB，按实际文件类型校验。小红书内部校验使用标题最多 20 字、正文最多 1,000 字和 1–9 张图片。首图为封面。B 站分类、模板、摘要和正文按专栏规则校验。确认页面同时展示标题、正文、话题、图片顺序和封面。模型改写稿在预览、复制和交接时保留适用标识，并提示使用目标平台的声明功能。 [B 站专栏投稿](https://open.bilibili.com/doc/4/b14b77b6-8889-8c8b-2e83-17c5a4c550fb) · [生成合成内容标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)

主要操作支持键盘、可见焦点和具体字段错误提示。状态使用文字标签，沙箱任务在列表、详情与统计显式标记。计时与试用证据填写在 [试用记录](./试用记录.md)。

### 访客预览与角色入口

未登录时可以直接浏览示例工作台、切换角色视角并打开示例详情。示例数据固定为虚构内容，页面标注「示例数据 · 只读」。访客页面只检查登录会话，工作室业务接口仍需登录及对应工作室成员身份。

| 实际角色 | 默认进入 | 主要入口 |
|---|---|---|
| 负责人 | 全部发布任务 | 原稿与审核、发布任务、发布账号、团队成员 |
| 编辑 | 原稿与审核 | 原稿与审核、发布任务、发布账号 |
| 审核员 | 待审核原稿 | 待审核和全部原稿、发布进度 |
| 运营 | 待回填任务 | 已审交接包、发布结果回填、原稿查阅 |
| 只读成员 | 已发布任务 | 发布结果与回执、原稿查阅 |

登录后按所选工作室的成员角色显示入口和操作。用户同时拥有个人工作室和参与协作的工作室时，初次进入优先打开协作工作室，之后可手动切换。负责人可在团队成员页通过已注册邮箱添加成员，或调整编辑、审核员、运营和只读成员的角色。成员重新进入工作台后应用更新的角色。写操作权限由 API 校验。

## 接口通用约定

- Web 使用同源 `/api`。登录、登出和当前用户沿用 `/auth/register`、`/auth/login`、`/auth/logout` 与 `/auth/me`。业务接口以下均相对于 `/api/workspaces/{workspaceId}`。
- API 先校验会话和工作室成员权限，再验证请求涉及的每个资源 ID。使用现有角色和 Zod 校验。确认、修改和排期以当前有效版本为准，结果记录归属任务所绑定的版本。
- 输入校验失败返回 `400` 和可定位字段的 `issues[]`，字段包含 `path` 与 `message`。未登录返回 `401`，角色权限不足返回 `403`，当前工作室查不到资源返回 `404`，业务状态冲突返回 `409`。数据库约束错误按统一契约映射为安全的业务响应。会话、平台令牌与飞书凭据只在服务端使用。账号相关响应使用显式字段，版本和任务内嵌的账号也沿用这一约定。 [数据库错误契约](./数据库设计.md#4510-数据库错误契约)
- API 接收带时区偏移的 ISO 8601 时间，`Z` 表示 UTC。API 返回 UTC 时间，页面按运营所选时区展示。以下接口表中「现有」指仓库已有路由，「新增」指实施契约。 [时间类型和接口边界](./数据库设计.md#17-时间类型和接口边界)

## 工作室、稿件与审核

首版工作室支持创建、切换及成员和设置管理，并保留历史业务数据。工作室没有物理删除接口。

| 方法与路径 | 状态 | 输入与返回 |
|---|---|---|
| `GET /members`、`POST /members`、`PATCH /members/{id}`、`DELETE /members/{id}` | 现有 | 沿用成员管理契约，权限修改按实际工作室校验。 |
| `GET /accounts`、`POST /accounts`、`PATCH /accounts/{id}`、`DELETE /accounts/{id}` | 现有，补授权状态和归档 | 账号包含平台、通道、显示名称、运营人以及授权与可用状态。授权记录保存授权方、范围、有效期和凭证引用。沙箱联调可用性由环境和通道配置判定。`DELETE` 改为归档并继续返回 `{ ok: true }`，有待发、派发中、已交接、已受理或审核中任务时返回 `409`。历史任务和证据可继续查询。 |
| `POST /accounts/{id}/authorize` | 新增 | 负责人或编辑为当前工作室的 B 站官方账号发起授权，返回授权地址。生成的一次性状态关联工作室、账号和操作人。 |
| `GET /api/channels/bilibili/oauth/callback` | 新增，完整路径 | 处理 B 站授权返回的 `code` 和 `state`。校验状态的绑定关系与有效期，由服务端交换并加密保存凭据，回到对应账号的授权结果页。 |
| `PATCH /notifications/feishu` | 新增 | 负责人配置或关闭当前工作室的飞书机器人。请求包含启用状态及配置所需的 webhook 地址和签名密钥。服务端限制为官方机器人地址，返回启用及配置状态。 |
| `GET /manuscripts`、`POST /manuscripts`、`GET /manuscripts/{id}`、`PATCH /manuscripts/{id}`、`DELETE /manuscripts/{id}` | 现有，补归档 | 沿用标题、正文、话题及现有返回。`DELETE` 改为归档并暂停仍待发的任务。原稿从普通列表移除，已有任务仍可读取其版本、审核、素材和结果。 |
| `POST /manuscripts/{id}/assets`、`GET /assets/{id}` | 现有，补校验 | 上传使用 multipart 的 `file` 字段，结果包含素材 ID。缺文件返回 `400`，超过 20 MiB 返回 `413`，非允许的实际图片格式返回 `415`。下载校验工作室和对象归属，以服务端判定的图片类型返回并加 `nosniff`。 |
| `GET /assets/{id}/thumbnail` | 新增图片预览 | 校验工作室归属后按比例生成最长边不超过 320px 的 WebP。工作台卡片使用缩略图，审核时可打开完整原图。无法生成预览返回 `422`。 |
| `POST /manuscripts/{id}/generate` | 已实现版本快照 | 输入 `platforms`，按现有规则生成，并以原稿图片创建快照。图片按上传时间和素材 ID 排序，首图为默认封面。再生成会取代旧版，暂停旧版尚未提交或交接的任务，并记录操作人和原因。 |
| `GET /variants/{id}`、`GET /variants/{id}/check` | 已实现快照读取 | 版本中的 `assets` 按 `position` 升序，`isCover` 标记封面。`/check` 返回 `variant`、`issues`、`imageCount`，图片数量取自版本快照。历史快照缺少有效指纹时返回 `snapshot_required`。 |
| `PATCH /variants/{id}` | 已实现版本快照 | 至少提交一项版本内容。支持单独更新文字、有序 `assetIds`、`coverAssetId` 或 `platformFields`。省略 `assetIds` 时沿用版本图片。封面引用同一快照内的图片，小红书首图为封面。返回新版本和实际暂停的任务数。完整快照内容未变化时返回 `400`（`variant_unchanged`），原审批与排期继续有效。历史版本可提交明确的图片清单生成完整快照，再重新确认。 |
| `POST /variants/{id}/confirm` | 已实现快照绑定 | 可带 `note`。校验快照后保存确认人、时间和 `snapshotHash`。重复确认返回首次记录。已被取代的版本或缺少有效快照的历史版本返回 `409`，须在新版确认。 |
| `POST /variants/{id}/reject` | 新增 | 提交非空 `reason`。当前草稿对应的退回记录包含审核人、时间和原因，并为作者登记待办。 |

## 发布任务与回执

已实现小红书人工通道的单账号排期、列表、详情、到点交接、截图和首次回填。路由前缀为 `/api/workspaces/{workspaceId}`。当前 `POST /tasks` 接收各含一个有效 ID 的 `variantIds` 和 `accountIds`，`scheduledAt` 使用带时区的 ISO 8601 字符串。批量、调期、取消、核对、更正和重试沿用下列后续实施标准。

### 排期

| 方法与路径 | 标准 |
|---|---|
| `POST /tasks` | 负责人或编辑提交 `variantIds`、`accountIds`、`scheduledAt`。按平台配对并去重，批次整体校验和提交。至少新增一条时返回 `201`，全部为已有配对时返回 `200`。响应为 `{ items }`，每项含 `id`、`accountId`、`variantId`、`status`、`scheduledAt` 和 `disposition`（`created` 或 `existing`）。 |
| `GET /tasks` | 支持 `status`、`accountId`、`manuscriptId`、`cursor`、`limit`，返回 `{ items, nextCursor }`。任务含计划时间、逐账号状态、`executionChannel`、`executionChannelStatus` 和 `isSandbox`。固定按创建时间和任务 ID 降序。 |
| `GET /tasks/{id}` | 返回任务、版本快照引用、当前回执和 `events`。事件按数据库 ID 升序返回，ID 序列化为字符串。事件含类型、前后状态、操作者、`createdAt` 和原因。详情显示证据、历史通道和操作人状态。 |
| `PATCH /tasks/{id}/schedule` | 负责人或编辑提交新 `scheduledAt`。当前版本已审、账号可用且任务仍为 `scheduled` 时更新原行。返回任务，保留原 ID 和幂等键，写入包含前后计划时间的事件。 |
| `POST /tasks/{id}/cancel` | 负责人或编辑可取消待发或暂停任务并提交原因。已交接任务由负责人核实尚未发布后取消，需同时提交核对依据。 |

批量排期输入无效或任一选择项无法按平台配对返回 `400`。资源不在当前工作室返回 `404`。版本未确认、已归档或账号不可用返回 `409`。失败时整批回滚并返回相应原因。已有配对和新配对可以在成功响应中混合返回。已有配对返回原任务和原计划时间，改时间走调期接口。

分页游标为服务端返回的不透明字符串，绑定工作室及当前筛选值，并编码上一页最后一条的 `(createdAt, id)`。下一页从严格小于该元组的记录开始，`limit` 默认 50，范围 1–100。无下一页时返回 `nextCursor: null`。无效游标或切换筛选后复用旧游标返回 `400`。结果按请求时的状态匹配，调期不会改变分页顺序。

首次领取时保存实际通道。列表和详情的 `executionChannelStatus` 使用 `known`、`not_dispatched` 和 `historical_unknown`，分别表示通道已确认、未派发和历史通道未知。`isSandbox` 对沙箱为 `true`，对已确认的真实通道为 `false`，未派发和历史未知为 `null`。统计仅将已确认真实通道的已发布记录计入真实数据，沙箱与历史未知单列。 [历史通道回填](./数据库设计.md#历史执行通道与操作人)

### 交接与核对

| 方法与路径 | 标准 |
|---|---|
| `GET /tasks/{id}/handoff` | 返回已审标题、正文、话题、图片顺序、封面和当前工作室权限下的素材下载链接。允许已交接任务的参与成员查看。 |
| `POST /tasks/{id}/evidence` | 以 multipart 的 `file` 字段上传任务截图，返回 `assetId`。沿用原稿素材的大小及格式校验。截图关联当前任务及工作室。 |
| `GET /tasks/{id}/evidence` | 通过工作室与任务鉴权读取当前回执截图。优先读取 `evidenceAssetId`，兼容期可读取核验通过的旧截图。无法取得可验证的截图时返回 `404`，任务详情保留待核对提示。 |
| `POST /tasks/{id}/result` | 负责人、编辑或运营提交 `state`（`published`、`failed` 或 `unknown`），可附 `remoteId`、`remoteUrl`、`evidenceAssetId` 和说明。已发布至少提供作品链接或本任务截图，更正要提交 `reason`。已取消任务仅负责人可通过本接口更正为 `published`。事务返回原任务的更新后回执，保留原取消记录及一条更正事件。 |
| `POST /tasks/{id}/verify` | 处理待核实任务，提交 `outcome`（`accepted`、`published`、`not_received` 或 `unresolved`）与证据说明。已受理须有文章 ID 并继续回读，已发布须有作品证据，明确未受理须说明核对依据，仍待核实须记录下一步。 |
| `POST /tasks/{id}/retry` | 负责人或编辑提交 `scheduledAt`。必须有明确未受理的证据且原审核有效，重新排期原任务。任务已取消或已有实际通道与当前配置不一致时返回 `409`。 |

当前交接包含 `taskId`、`account`、`variantId`、`version`、`title`、`body`、`tags` 和按顺序排列的 `assets`。每张图片含 `assetId`、`position`、`isCover` 和素材下载 `url`。负责人、编辑和运营可读取交接包、上传截图及回填。首次回填返回 `200` 和当前回执，后续写入返回 `409`。截图下载读取当前回执的 `evidenceAssetId`。

排期、提交、交接、回填、核对、改期和取消均写入 `TaskEvent`，与任务状态和回执一并提交。核对未决时保留 `unknown`。已取消更正时，权限不足返回 `403`，缺原任务证据或原因返回 `400`，任务已被更正或状态冲突返回 `409`。更正只更新原任务的账本记录。

详情的当前回执可为 `submitted`、`under_review`、`published`、`failed` 或 `unknown`。官方受理立即保存文章 ID。已确认的平台发表时间与文章 ID 可用于展示官方证据。人工通道交接后默认 4 小时无回填再次提醒，飞书投递结果及终态由独立记录提供。 [回执和提醒契约](./数据库设计.md)

## 页面与接口验收

- 用两个工作室和不同角色验证列表、详情、确认、排期、素材下载、回填和凭据响应的权限边界。
- 覆盖不存在、跨工作室、非图片、超限和旧素材预览。验证账号和原稿归档后，已发布任务的审批、结果及截图仍可访问。
- 验证负责人可以凭本任务证据更正已取消任务一次，其他角色越权、重复更正和已取消重试均正确拒绝。覆盖可读旧截图与核对失败的旧截图。
- 核对历史通道未知、未派发和沙箱标签，以及它们在统计中的归类。验证逾期飞书提醒重启后进入跳过，站内待办可以继续使用。
- 验证第 51 个账号可新增、查询并单独排期。50 个账号批量任务可独立查看结果。
- 确认后换图与重生成都会产生新版本。旧版待发任务暂停，已经提交或交接的任务继续追踪旧版本。
- 重复创建与调期均保留原任务。经人工核对仍不明确时保持待核实。仅在有明确未受理证据时允许重试。
- 验证正常、全重复和新旧混合的 `201` 或 `200` 响应。任一配对失败时批次无新增。分页覆盖创建时间相同的多条任务、翻页期间的调期以及换筛选后复用游标。
- 用真实图文走通小红书站内待办、飞书、逾期、回填和补发更正。B 站使用有权限的账号验证提交与真实状态回读。各阶段通过标准见 [首版开发计划](../DEVELOPMENT_PLAN.md)。
