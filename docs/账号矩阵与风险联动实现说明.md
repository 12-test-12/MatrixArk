本文记录 MatrixArk 在“多账号集中管理、不依赖官方开放平台前置审批”方向上的完整改造与实现细节，作为后续开发、排障、迁移和运维的长期备忘录。全部改动保持工作室多租户隔离、加密 AAD 绑定及人工交接/官方通道兼容性。

## 1. 背景与解决的问题

1. **脱离官方开放平台卡点**：在开放平台应用尚未审核通过前，仍可通过 **网页扫码（QR）**、**账号密码托管**、**Cookie 导入** 三种方式接入 B 站 / 小红书账号，且接入后即可进入人工交接排期流程（`availableForHandoff: true`）；同时保留旧版仅填 UID 的 B 站 `manual_uid`（`manual-bili-uid:`）拦截策略，确保向后兼容。
2. **单一归属矩阵组**：支持跨平台创建运营矩阵组，数据模型上强制 **一个账号最多只能归属一个矩阵组**，彻底避免同一账号同时挂在多个分组下引起运营与排期混淆。
3. **风险感知与飞书联动**：建立自动体检、发布异常联动与人工上报风险闭环，通过工作台飞书群机器人实现实时告警与解除同步。

### 2.2 新增与扩展表结构

1. **`MatrixGroup`（矩阵组）**
   - 字段：`id`、`workspaceId`、`name`、`color`（默认 `blue`）、`description`、`sortOrder`、`createdAt`、`updatedAt`（所有时间列均为 `timestamptz(3)`）。
   - 约束：`@@unique([workspaceId, name])`（同一工作室内矩阵组不重名）、`@@unique([workspaceId, id])`（供复合外键引用）。
   - 应用账号权限（`matrixark_app`）：`SELECT, INSERT, UPDATE, DELETE`。
2. **`ChannelAccount` 扩展字段**
   - 接入与分组：`accessMethod`、`groupId`（单外键，复合外键 `(workspaceId, groupId) -> MatrixGroup(workspaceId, id)`，保证同一账号至多属于本工作室内 1 个矩阵组）、`alias`、`tags`、`pinned`。
   - 加密凭据：`loginIdentifier`（掩码展示）、`passwordCiphertext` / `passwordKeyId`、`cookieCiphertext` / `cookieKeyId` / `cookieUpdatedAt`。
   - 风险状态：`riskStatus`、`riskReason`、`riskDetectedAt`。
3. **`AccountRiskEvent`（账号风险事件日志）**
   - 字段：`id`、`workspaceId`、`accountId`、`level`（`AccountRiskStatus`）、`kind`、`message`、`feishuStatus`、`feishuError`、`actorId`、`resolvedAt`、`resolvedById`、`createdAt`。
   - 应用账号权限（`matrixark_app`）：`SELECT, INSERT, UPDATE`（禁止 `DELETE`，保留审计追溯）。
4. **`NotificationSetting` 扩展字段**
   - 新增 `riskAlertEnabled Boolean @default(true)`，独立控制账号风险事件是否触发飞书群推送。

## 3. 核心业务实现（后端）

### 3.1 凭据加密与 Cookie 解析

- 实现位置：[apps/api/src/accounts/account-secrets.ts](file:///D:/MatrixArk/apps/api/src/accounts/account-secrets.ts)
- **加密**：复用 [platform-app.ts](file:///D:/MatrixArk/apps/api/src/accounts/platform-app.ts) 的 `encryptPlatformSecret` / `decryptPlatformSecret`（AES-256-GCM，`keyId = 'platform-local-v1'`），通过 AAD `['account-password' | 'account-cookie', workspaceId, accountId]` 与工作室及账号强绑定。
- **脱敏**：`maskLoginIdentifier` 对手机号、邮箱与普通账号名统一脱敏后写入 `ChannelAccount.loginIdentifier`。
- **Cookie 兼容解析**：`parseCookieHeader` 同时支持标准 `Header` 字符串（允许带 `Cookie:` 前缀或换行分隔）及浏览器导出的 JSON 数组 / 键值对象，且 `validatePlatformCookie` 按平台校验必备会话键（B 站要求 `SESSDATA`，导入后再调 `nav` 接口核验登录态与 UID；小红书要求 `web_session` / `a1` / `customer-sso-sid` 等）。

### 3.2 三种账号接入方式与可控解密

- 实现位置：[apps/api/src/accounts/account-onboarding.service.ts](file:///D:/MatrixArk/apps/api/src/accounts/account-onboarding.service.ts)、[apps/api/src/accounts/accounts.controller.ts](file:///D:/MatrixArk/apps/api/src/accounts/accounts.controller.ts)
- **1）扫码接入（QR）**：
  - **B 站网页端扫码**：`POST /api/workspaces/:workspaceId/accounts/bilibili/qr` 生成 180 秒有效二维码门票（对接 `https://passport.bilibili.com/x/passport-login/web/qrcode/generate`）；`POST .../bilibili/qr/:id/poll`（带 1500ms 轮询保护）确认登录后通过 `https://api.bilibili.com/x/web-interface/nav` 核验 `mid` 与 `uname`，加密保存完整登录 Cookie（`accessMethod: 'qr_login'`，`externalId` 为 `bili-web-uid:<mid>`），并自动解除该账号此前未解决的风险事件。
  - **小红书扫码**：沿用 [xiaohongshu-identity.service.ts](file:///D:/MatrixArk/apps/api/src/accounts/xiaohongshu-identity.service.ts) 身份核验流，创建/更新时标注 `accessMethod: 'qr_login'`。
- **2）账号密码托管（Password）**：
  - `POST /api/workspaces/:workspaceId/accounts/password`：接收平台、显示名、登录账号、密码及可选 B 站 UID/主页、矩阵组、别名、标签；完整账号与密码加密存储在 `passwordCiphertext` 中，数据库明文字段仅存掩码后的 `loginIdentifier`。
- **3）Cookie 导入（Cookie）**：
  - `POST /api/workspaces/:workspaceId/accounts/cookie`：支持新增账号或针对已有账号刷新 Cookie。B 站会现场联网校验 `nav` 接口返回真实登录态，小红书按会话标识哈希生成或匹配 `xhs-cookie:<hash>` 并加密入库。
- **可控解密读取**：
  - `GET /api/workspaces/:workspaceId/accounts/:id/credentials`：严格校验 `account:manage` 权限且禁止试用工作室访问，返回解密后的账号/密码或 Cookie 供人工登录交接使用。
- **人工交接放行判定**：
  - [publish-account.ts](file:///D:/MatrixArk/apps/api/src/accounts/publish-account.ts) 中 `isUnverifiedBilibiliAccount` 仅认定 `accessMethod === 'manual_uid'` 或 `externalId` 以 `manual-bili-uid:` 开头的历史仅 UID 记录为未核验；`qr_login`、`password`、`cookie` 均返回 `availableForHandoff: true`。

### 3.3 矩阵组管理与批量操作

- 实现位置：[apps/api/src/accounts/matrix-groups.service.ts](file:///D:/MatrixArk/apps/api/src/accounts/matrix-groups.service.ts)
- 接口列表（路由均位于 `/api/workspaces/:workspaceId/accounts` 下，静态路由置于 `:id` 参数路由之前）：
  - `GET /groups`：返回矩阵组及每组活跃账号数（`accountCount`）、可用账号数（`availableCount`）、风险账号数（`riskCount`）。
  - `POST /groups` / `PATCH /groups/:groupId`：创建与更新名称、配色（`blue | rose | emerald | amber | violet | cyan | slate`）、说明、排序；名称冲突返回 `409`。
  - `DELETE /groups/:groupId`：事务内加锁后先清空组内账号 `groupId = null` 再删除矩阵组，保留全部账号及历史发布任务。
  - `POST /batch`：支持对勾选账号批量执行 `set_group`（替换单一 `groupId`）、`set_operator`、`set_pinned`、`add_tags`、`clear_tags`。
  - 所有传入 `groupId` 的写入点均经过 `assertWorkspaceGroup` 校验，确保无法引用其他工作室的矩阵组。

### 3.4 风险体检、人工标记与飞书群机器人联动

- 实现位置：[apps/api/src/accounts/account-risk.service.ts](file:///D:/MatrixArk/apps/api/src/accounts/account-risk.service.ts)、[apps/api/src/notifications/notifications.service.ts](file:///D:/MatrixArk/apps/api/src/notifications/notifications.service.ts)
- **自动检查项（`checkAccountHealth`）**：
  1. 平台限流冷却期（`rateLimitedUntil > now` -> `rate_limited` / `risk`）；
  2. 官方 OAuth 授权过期或 24 小时内临期（`auth_expired` / `risk`、`auth_expiring` / `warning`）；
  3. 托管 Cookie 解密失败、B 站 `nav` 探测未登录（`code === -101`）、小红书缺失核心会话字段（`cookie_expired` / `risk`）；
  4. 若之前属于系统自动管理类的风险（`autoManagedKinds`），再次体检通过时自动调用 `resolveRisk` 恢复为 `normal`。
- **定时巡检**：
  - [apps/api/src/worker.ts](file:///D:/MatrixArk/apps/api/src/worker.ts) 注册 `accountRisks.scanDueAccountHealth()`，每 10 分钟（`600_000ms`）巡检未归档账号：每轮按最近体检时间取最旧的 15 个，体检完成（含小红书只做会话字段校验）都会推进 `authCheckedAt`，多账号工作室能逐步轮转到全部账号。
- **人工上报 / 解除与接口**：
  - `POST /accounts/:id/health-check`：立即执行单账号体检；
  - `POST /accounts/:id/risk`（允许 `operator` 及以上拥有 `task:result` 权限者上报风控滑块/异常）；
  - `POST /accounts/:id/risk/resolve`（`account:manage` 权限解除风险，可选通知飞书）；
  - `GET /accounts/risks`：按工作台或单账号查询最近 50 条风险事件日志（含飞书投递状态）。
- **飞书通知联动**：
  - `AccountRiskService.recordRisk` 对 6 小时内同一账号同类未解除自动风险做发送去重（`recentSame`）；首次触发或人工 `forceNotify` 时调用 `NotificationsService.sendAccountRiskAlert`。
  - 在 `enabled && riskAlertEnabled && webhookCiphertext` 开启时发送签名飞书文本提醒（含工作室、平台、账号别名/名称、所属矩阵组、负责人与说明）；试用工作室在 `trialAvailable` 时按模拟发送记为 `sent`。
- **发布异常与工作台角标联动**：
  - [apps/api/src/tasks/tasks.service.ts](file:///D:/MatrixArk/apps/api/src/tasks/tasks.service.ts) 在官方投稿回执 `failed` 时触发 `accountRisks.recordRisk`，并在 `/tasks/performance` 增加 `groupId` 查询过滤与账号分组/别名汇总展示。
  - [apps/api/src/workspaces/workspaces.controller.ts](file:///D:/MatrixArk/apps/api/src/workspaces/workspaces.controller.ts) 与 [trial-workspace.service.ts](file:///D:/MatrixArk/apps/api/src/workspaces/trial-workspace.service.ts) 在 `/workbench-summary` 中增加 `riskAccounts` 统计字段。

## 6. 运维使用备忘与变更记录

### 日常运维与排障备忘
- **Windows 下 Prisma 客户端生成**：如果执行 `pnpm db:generate` 遇到 `query_engine-windows.dll.node` `EPERM` 文件锁报错，需先停止占用该 DLL 的本地 API（`@matrixark/api`）与 Worker（`dist/worker.js`）进程，再执行生成与迁移，最后重新启动服务（`pnpm dev:api` / `pnpm dev:worker`）。
- **数据库迁移流程**：新增或变更表结构后，除运行 `migrate deploy` 外，还需对目标库执行 [apps/api/prisma/app-privileges.sql](file:///D:/MatrixArk/apps/api/prisma/app-privileges.sql)，确保 `matrixark_app` 拥有 `MatrixGroup` 与 `AccountRiskEvent` 的对应最小权限。
- **单组约束核查**：账号只能属于一个矩阵组，后端所有新建、编辑、批量移动接口均会通过 `assertWorkspaceGroup` 校验 `groupId` 归属；解散矩阵组会清空组成员的 `groupId`，但不会删除账号或历史任务。
- **官方开放平台审批前后的过渡**：未配置/未通过开放平台时使用 `qr_login`、`password`、`cookie` 走人工交接通道；后续开放平台通过并绑定 `oauth` 授权后，原有人工账号、历史任务与矩阵组都保留可继续使用，但官方记录是**新增的一条账号**——开放平台 `openid` 与手工接入的 `bili-web-uid:<mid>` / `manual-bili-uid:<mid>` 不是同一标识，无法自动合并，需要人工把旧的人工账号归组或归档，避免同一作者出现两条可排期账号。

## 7. 发布入口、无应用凭据验证与成效趋势

记录日期为 2026-11-26。第 5 节记录矩阵与风险联动的整体验证，本节补充发布通道边界、零凭据验证和趋势图口径。

### 7.1 账号归属与发布通道

- 旧版 B 站仅凭名称、UID 或空间链接新增账号的入口已移除。历史 `manual_uid` 及 `manual-bili-uid:` 记录保留供追溯，发布列表标为「待官方授权」。服务端在排期、恢复和领取时拦截这类记录，到期旧任务转为暂停。已经交接的旧任务仍保留审计记录，交接包和「已发布」回填入口受限。 [账号判定](../apps/api/src/accounts/publish-account.ts) · [任务处理](../apps/api/src/tasks/tasks.service.ts)
- 正式 B 站专栏自动投稿从「发布账号 → B 站」配置开放平台应用开始，使用应用的 `client_id` 和密钥，由目标账号在 B 站确认授权，并核验 `USER_INFO`、`ATC_BASE` 和 `ATC_DATA`。网页扫码、Cookie 和密码登记可进入人工交接通道。密码登记的 `identityVerified` 为 `false`，人工交接资格与官方授权状态分别判断。小红书官方扫码用于核验身份，稿件由运营在创作中心提交。 [账号列表接口](../apps/api/src/accounts/accounts.controller.ts) · [B 站官方鉴权说明](https://open.bilibili.com/doc/4/8673959e-f7bb-56e6-6e68-d225f971b81b) · [小红书官方扫码说明](https://openaccount.xiaohongshu.com/docs/device-flow)
- 矩阵合并后，后端按接入方式放行 B 站人工排期，任务详情、回填入口和飞书交接提醒也沿用同一判定：只有历史仅 UID（`manual_uid` / `manual-bili-uid:`）账号被拦截，扫码、Cookie、密码接入的 B 站人工账号可以取交接包、回填结果并收到飞书交接提醒。集成测试覆盖已核验 B 站人工账号的排期、交接包、主页链接和交接提醒，以及历史仅 UID 账号交接提醒的跳过。 [任务详情](../apps/web/app/tasks.tsx) · [交接提醒](../apps/api/src/notifications/notifications.service.ts)

### 7.3 作品成效趋势绘制

- 趋势图按本地日历日绘制，同一天以最新采集快照为准。所选时间范围内，未采集的日期和指标在图上按 0 绘制，圆点标记实际采集值。悬停空白日期提示「当天无成效记录，按 0 绘制」。采集明细保留原始缺失值、来源、录入人和时间，补出的 0 只参与图表展示。
- 数值变化使用三次贝塞尔曲线连接，转折点以水平切线平滑衔接，曲线保持在相邻日期的数值范围内，相同值之间画水平线。浏览器用原有作品验证了近 90 天视图，各指标包含 2 天实测值和 88 天补零，空白日期悬停显示 0。Web 类型检查通过。 [趋势图实现](../apps/web/app/performance.tsx)
