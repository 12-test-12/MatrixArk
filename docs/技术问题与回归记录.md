# MatrixArk 技术问题与回归记录

核对基线为 `2e9fefb`。本记录面向开发和验收，覆盖工作台、API、Worker、数据库及部署。实现契约以 [技术设计](./技术设计.md) 和 [功能与接口设计](./功能与接口设计.md) 为准，开发防错与避坑规则以 [常见技术陷阱与开发防错规范](./常见技术陷阱与开发防错规范.md) 为准。

修改前先检查本次涉及的模块和对应回归项。遇到相似症状时，先确认运行版本、触发条件和实际返回，再对照旧修复定位。改动完成后记录验证场景、结果和提交号。问题修完后把条目移到「已修复与回归标准」，保留原始症状和验收依据，后续改动可以直接复查。

## 一、当前待解决的问题

### 1. 发布任务缺异常处理闭环

目前可创建排期、交接和回填。填过「待核实」、因改稿或凭据失效被暂停、选错账号或时间的任务，工作台缺少核对、恢复、取消、改期、结果更正和安全重试入口。再次提交同一账号与版本会返回原任务，原计划时间也会保留。

**验收**　改期保留原任务 ID 和幂等键。取消、核对和更正记录操作者、时间、原因及证据。平台是否受理不明确时进入核对，确认未受理且审核仍有效时才允许在原任务上重试。覆盖正常操作、重复操作、并发领取和迟到回执。 [现有任务接口](../apps/api/src/tasks/tasks.controller.ts) · [排期与核对契约](./功能与接口设计.md#交接与核对)

### 2. B 站专栏还缺网页授权闭环和真实回执

工作台可以保存应用凭据并用访问令牌绑定账号。令牌及到期时间仍需人工填写。授权失效后，已受理任务的状态查询会提前退出。仓库有模拟投稿和状态回读用例，真实文章从受理到发表的证据仍待登记。

**验收**　完成浏览器授权回调及状态校验。排期时能识别预计执行前过期的授权。重新授权后能继续核对已有文章 ID 和记载回执，保持原任务的提交记录。真实联调用一篇专栏验证平台受理、审核状态和发表证据。 [账号界面](../apps/web/app/accounts.tsx) · [回执轮询](../apps/api/src/tasks/tasks.service.ts) · [授权联调](./技术设计.md#b-站授权联调)

### 3. 官方视频投稿及小红书自动发布尚未接通

视频已经支持共用素材、审核和人工交接。官方通道当前在排期时拒绝视频任务。小红书扫码用于身份核验，已核验账号可用于人工交接。B 站专栏上传和读取文章成效的能力与视频投稿分别验收。

**验收**　按开发计划先接 B 站视频的分片上传、投稿和作品状态回读。验证网络中断、限流及平台已受理但本地未收到回执三种情况。增加其他正式通道前，用授权账号验证真实发布和回执能力。 [官方排期校验](../apps/api/src/tasks/tasks.service.ts) · [视频实施顺序](../DEVELOPMENT_PLAN.md#当前实施顺序与视频扩展)

### 4. 完整部署、Worker 监控及恢复演练待补

Compose 当前只有迁移和 API。健康接口只能反映 API 能否查询数据库，无法发现 Worker 停止、任务积压或飞书提醒未发送。数据库恢复点、素材目录和凭据密钥还需要一起做恢复验证。

**验收**　交付 Web、API、Worker 和独立迁移步骤。主动停掉 Worker 后能发现异常。恢复期间可以暂停派发，核对可能已经提交的平台任务。演练同时验证数据库、历史素材、平台与通知密钥，以恢复时间 2 小时、数据库数据损失窗口 1 小时为计划目标。 [部署配置](../docker-compose.yml) · [健康接口](../apps/api/src/health.controller.ts) · [恢复标准](../DEVELOPMENT_PLAN.md#首版验收)

### 5. 审核退回和旧稿可见性待补

审核接口当前支持确认。原稿列表只返回最近 100 条，待审筛选在浏览器里执行，较早的待审稿可能从列表中消失。

**验收**　服务端按审核状态筛选并分页。造 101 条以上原稿，仍能找到最早的待审稿。退回要保存原因和审核人，作者可以从待办定位对应版本。 [原稿列表](../apps/api/src/content/manuscripts.controller.ts) · [审核接口](../apps/api/src/content/variants.controller.ts)

### 6. 混合通道的峰值派发延迟待验证

现有集成测试验证了 50 个账号的批量排期、去重和第 51 个账号单独排期。单 Worker 当前会等待上一条官方任务完成，慢投稿可能拖延其他账号和人工交接任务。

**验收**　在保留同账号串行的前提下，模拟 50 个任务同时到期及一个平台请求超时，记录各账号从计划时间到实际领取或交接的延迟，并核对告警和待核实记录。 [Worker 派发](../apps/api/src/tasks/tasks.service.ts) · [批量回归用例](../apps/api/test/manual-handoff.test.mjs)

### 7. 回填截图在并发失败时可能遗留文件

截图先写磁盘，再登记到任务。两步之间如果另一位运营先完成了回填，登记会因任务状态变化而失败，文件可能留在磁盘。

**验收**　模拟两人同时处理，失败的一方只在确认数据库没有记录对象引用时清理本次上传。提交结果不明时保留文件供核查。可以复用视频上传现有的处理方式。 [截图上传](../apps/api/src/tasks/tasks.controller.ts) · [视频上传](../apps/api/src/content/manuscripts.controller.ts)

### 8. 公网试点需补登录限流和注册控制

登录和注册是公开入口，当前代码未显示请求频率限制。注册会创建工作室。公网试点前应明确允许的注册范围，并限制重复登录请求。

**验收**　试点成员能正常访问。连续失败请求与注册超限会受控返回，其他成员的正常登录及工作室切换不受影响。 [认证入口](../apps/api/src/auth/auth.controller.ts)

### 9. CI 选择路径和关键浏览器回归待补

仅修改认证、工作室权限或飞书服务目录时，当前选择规则不会自动运行 PostgreSQL 集成测试。作品成效和账号设置已有隔离浏览器验证，尚未纳入仓库流水线。

**验收**　相关目录变动会触发依赖的集成检查。增加一条登录后从原稿到排期、交接、回填和查看结果的浏览器关键路径。登录态模拟数据按接口契约返回，特别是成员列表使用数组，任务分页结果使用带 `items` 的对象。 [流水线选择规则](../infra/ci/select-targets.mjs) · [CI 配置](../.github/workflows/matrixark.yml)

## 三、按改动选择验证

- **前端与接口联动**　跑 `pnpm typecheck` 和相关应用构建，再从真实页面走一遍受影响操作。重点覆盖加载、空数据、错误提示和权限差异，避免只检查成功页面。
- **排期、授权、回执、提醒或作品成效**　优先扩展 [现有发布集成测试](../apps/api/test/manual-handoff.test.mjs)，用独立数据库和模拟平台接口验证异常路径。真实平台联调另记账号授权、平台作品 ID 和回执证据。
- **版本、素材或数据库迁移**　复查 [快照集成测试](../apps/api/test/variant-snapshot.test.mjs) 与 [数据库 CI](../infra/ci/check-database.sh)。涉及历史结构时同时核对新库和已有数据的升级。部署前备份数据库与素材密钥，使用已审查的迁移执行。
- **本机接口报旧路由**　先核对监听端口上的进程及已加载版本，再检查数据库迁移、API 路由及 Worker 状态。Windows 上 Prisma 客户端生成遇到 DLL 文件锁时，先确认占用进程，按本机部署方式更新客户端。重启后验证健康接口和实际功能路由。

## 四、已有验证证据

`b000f0a` 的实现已通过前后端构建、全仓类型检查、30 项单测和本机隔离 PostgreSQL 上的 12 项集成测试。成效趋势已用隔离数据在浏览器验证账号入口、筛选、折线、单点及零值录入。`2e9fefb` 追加了应用凭据缺失时暂停任务的回归用例。生产恢复演练、真实平台投稿和峰值压测仍需按第一节各条目留下实测结果。
