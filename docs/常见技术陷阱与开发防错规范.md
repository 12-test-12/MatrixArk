# MatrixArk 常见技术陷阱与开发防错规范

> **适用范围**：全仓开发、代码重构、代码审查（Code Review）与交付验收。  
> **核心原则**：凡进入本规范的缺陷与技术陷阱，后续开发一律禁止再次犯下相同错误；任何新功能或改动必须对照本指南完成自检。

---

## 零、提交前防错自检清单（Pre-Flight Checklist）

在提交任何代码或发起评审前，必须确认以下每一项已通过核验：

- [ ] **前端样式**：没有在 `<body>` 或 `<html>` 上使用 `overflow: hidden` 来锁定弹窗背景；模态弹窗已使用 `dialog:modal { overscroll-behavior: contain; }`。
- [ ] **弹窗交互**：所有模态对话框均实现了遮罩关闭（声明 `closedby="any"` 并在不支持的环境下以几何边界比对回退），且在操作执行中支持锁定退出。
- [ ] **表单校验**：没有使用全局 `:invalid` 导致页面刚加载或未输入完毕就过早变红；统一使用 `:user-invalid`。
- [ ] **空值安全**：所有可能为空的数组、集合访问均带有可选链或默认空数组，如 `(item.assets ?? []).length`，杜绝访问未定义属性导致白屏。
- [ ] **MIME 检测**：涉及文件上传接口的 `Content-Type` 比对，已使用 `.split(';')[0].trim().toLowerCase()` 提取主类型，避免因附加参数误报 `415`。
- [ ] **通用请求封装**：前端底层的 `fetch` / `api()` 封装绝不硬编码二进制媒体类型（如强制 `video/mp4`），并完整透传调用方的自定义请求头。
- [ ] **上传失败状态恢复**：前端文件选择与上传失败后，除了“重试”按钮，必须提供“取消/清除”按钮，保证用户能够退出错误预览并恢复原状。
- [ ] **调度与幂等**：发布排期的幂等键（Idempotency Key）严禁将排期时间纳入计算；同账号只允许单个活跃任务在派发。
- [ ] **平台通道匹配**：视频资产与图文专栏等不支持视频的通道在调度层必须有硬约束校验与明确提示。
- [ ] **Windows 兼容**：本地构建与多命令执行避免使用 Bash 专有的 `&&` 串联，统一使用 `;` 或 npm 脚本封装。

## 一、现代 Web 前端与交互样式规范

### 1.1 模态弹窗滚动穿透与页面抖动（禁止 `body { overflow: hidden }`）

* **错误现象**：在弹窗打开时通过 JS 或 `:has(.dialog[open])` 给 `body` 添加 `overflow: hidden`。这会移除浏览器根滚动条，导致页面整体发生剧烈的横向布局位移（Layout Shift），并且会导致页面内已存在的 `position: sticky` 元素失效。
* **根因分析**：传统的背景锁屏方案破坏了根视口排版上下文。现代 Web 标准已提供顶层隔离机制。
* **正确规范**：
  ```css
  /* 强制采用原生滚动行为隔离 */
  dialog:modal {
    overscroll-behavior: contain; /* 阻止模态框内部滚动手势穿透到下层页面 */
  }

  dialog::backdrop {
    overflow: hidden; /* 将 backdrop 转为不可滚动容器 */
    overscroll-behavior: contain; /* 阻止遮罩上的滑动手势串联 */
  }
  ```

---

### 1.2 对话框 Light Dismiss 遮罩误触关闭

* **错误现象**：使用 `onClick={(e) => { if (e.target === dialog.current) dialog.current.close(); }}` 实现点击遮罩关闭。当用户点击对话框本身的内边距（padding）或子容器缝隙时，`event.target` 同样是 `<dialog>` 元素，导致用户在填写表单时被意外关闭，丢失输入内容。
* **正确规范**：
  1. 声明原生属性 `closedby="any"`（React 中需转义 `{...({ closedby: action.busy ? 'none' : 'any' } as any)}`）。
  2. 降级回退必须检查光标点击坐标是否在对话框的内容几何矩形之外：
  ```tsx
  <dialog
    ref={dialog}
    {...({ closedby: action.busy ? 'none' : 'any' } as any)}
    onClick={(event) => {
      if (action.busy || !dialog.current) return;
      if (!('closedBy' in HTMLDialogElement.prototype)) {
        const rect = dialog.current.getBoundingClientRect();
        const isInside = (
          rect.top <= event.clientY &&
          event.clientY <= rect.top + rect.height &&
          rect.left <= event.clientX &&
          event.clientX <= rect.left + rect.width
        );
        if (!isInside) dialog.current.close();
      }
    }}
  >
  ```

---

### 1.3 表单交互校验时机（严禁直接使用 `:invalid`，统一使用 `:user-invalid`）

* **错误现象**：直接使用 `input:invalid` 渲染红色边框和警示背景。导致表单初次渲染、用户刚聚焦输入第一个字符时，输入框立即变红报错，造成严重的心理干扰与劣质交互体验。
* **正确规范**：
  1. 仅使用 `:user-invalid` 和 `:user-invalid:focus`，浏览器只会在用户修改并失焦（blur）离开或主动点击提交后才触发错误态。
  2. 针对范围滑块（range）做排除，避免滑块被应用文本框的边框底色：
  ```css
  input:not([type=file]):not([type=range]):user-invalid,
  textarea:user-invalid,
  select:user-invalid {
    border-color: #d93025;
    background-color: #fff8f8;
  }

  input:not([type=file]):not([type=range]):user-invalid:focus,
  textarea:user-invalid:focus,
  select:user-invalid:focus {
    border-color: #d93025;
    box-shadow: 0 0 0 3px rgba(217, 48, 37, 0.15);
  }
  ```

---

### 1.4 全局滚动条尺寸与无障碍操作靶区

* **错误现象**：全局盲目定义 `scrollbar-width: thin;`。虽然视觉上细腻，但大大缩小了鼠标拖拽和触控交互的实际点击靶区，严重违反无障碍可操作性准则。
* **正确规范**：
  保持标准滚动条宽度 `scrollbar-width: auto;`，仅通过 `scrollbar-color` 统一视觉风格。对于旧版 WebKit 伪元素，必须包裹在 `@supports not (scrollbar-color: auto)` 内部，避免污染已支持标准语法的现代浏览器。
  ```css
  * {
    box-sizing: border-box;
    scrollbar-width: auto;
    scrollbar-color: #cbd2e3 transparent;
  }

  @supports not (scrollbar-color: auto) {
    *::-webkit-scrollbar { width: 8px; height: 8px; }
    *::-webkit-scrollbar-track { background: transparent; }
    *::-webkit-scrollbar-thumb { background: #cbd2e3; border-radius: 999px; }
  }
  ```

---

### 1.5 Next.js App Router 首屏主题声明与画布闪烁（FOUC）

* **错误现象**：在根 `layout.tsx` 的 `export const metadata: Metadata` 中配置 `colorScheme: 'light'`。Next.js 会在构建和运行时抛出告警（`Unsupported metadata colorScheme is configured in metadata export`）且配置无效，可能引发暗色系统下的浅色画布瞬间反差闪烁。
* **正确规范**：在 Next.js App Router 中，`colorScheme` 属于视口配置，必须单独导出 `viewport`：
  ```tsx
  import type { Metadata, Viewport } from 'next';

  export const metadata: Metadata = {
    title: 'MatrixArk · 内容工作台',
    description: '...',
  };

  export const viewport: Viewport = {
    colorScheme: 'light',
  };
  ```

---

### 1.6 数据集合与可选属性安全访问

* **错误现象**：直接读取可选字段数组长度或方法，如 `manuscript.assets.length` 或 `task.receipt.url`。当面对历史稿件、无图稿件或未回填任务时，产生 `TypeError: Cannot read properties of undefined`，导致整个 React 组件树崩溃白屏。
* **正确规范**：
  1. 数组访问一律加防空保护：`(manuscript.assets ?? []).length`。
  2. 接口设计契约：后端与 Mock 数据返回空集合时，必须显式返回空数组 `[]`，严禁返回 `null` 或直接省略该键。

## 二、音视频与素材文件流式处理规范

### 2.1 请求头 MIME 类型检测（禁止严格等值匹配）

* **错误现象**：在上传接口中使用 `request.get('content-type') !== 'video/mp4'`。当标准的客户端、代理服务器或反向代理网关附加编码信息（例如 `video/mp4; charset=binary` 或指定音视频编解码器 `video/mp4; codecs="avc1.42E01E"`）时，上传会被直接判定为非法格式并抛出 `415 UnsupportedMediaTypeException`。
* **正确规范**：
  ```ts
  // 提取分号前的媒体主类型并转小写
  const contentType = request.get('content-type')?.split(';')[0]?.trim().toLowerCase();
  if (contentType !== 'video/mp4') {
    throw new UnsupportedMediaTypeException('请选择 MP4 视频');
  }
  ```

---

### 2.2 前端底层请求封装通用性（解耦写死媒体类型）

* **错误现象**：在公用底层 `api.ts` 的 `fetch` 封装中，直接以 `body instanceof Blob` 判定并将 `content-type` 一律写死为 `video/mp4`，且未合并调用方外部传入的 `options.headers`。这导致后续图片 Blob、文本 Blob、导出文件等其他二进制请求全部被错误标记。
* **正确规范**：
  ```ts
  const blob = options.body instanceof Blob ? options.body : undefined;
  const defaultHeaders: Record<string, string> = {};
  if (blob) {
    defaultHeaders['content-type'] = blob.type || 'video/mp4';
    defaultHeaders['x-video-size'] = String(blob.size);
  } else if (options.body !== undefined && !form) {
    defaultHeaders['content-type'] = 'application/json';
  }
  // 必须保留并合并调用方的自定义 headers
  const headers = options.headers 
    ? { ...defaultHeaders, ...options.headers }
    : (Object.keys(defaultHeaders).length ? defaultHeaders : undefined);
  ```

---

### 2.3 文件选择与异步上传的状态机闭环（必须支持取消/重置）

* **错误现象**：用户选择了一个大视频或图片文件，若上传遇到网络中断或格式校验失败，界面仅提供“重试上传”按钮。用户如果想放弃更改或重新选择其他文件，无法清除本地选中的文件预览，界面永久锁死在错误态，只能强行刷新页面。
* **正确规范**：
  在任何涉及本地文件暂存与异步上传的组件中，错误展示区域必须成对提供「重试」与「取消」操作，点击取消时应一并清除本地 `pickedFile` 以及相关的错误 Action 状态。

---

### 2.4 MP4 容器盒模型（ISO/IEC 14496-12）解析边界

* **错误现象**：扫描 MP4 文件二进制盒（Box）时使用了 `if (length > 8) boxes.add(type);`。按照国际规范，8 字节恰好是合法紧凑盒（4 字节长度 + 4 字节类型，空 payload），该判断会导致规范的 8 字节 Box 无法计入统计集合。
* **正确规范**：
  只要长度在 `8 <= length <= size - offset` 范围内，均应记录盒类型：`boxes.add(type);`。

---

### 2.5 文件名字符集与存储哈希隔离

* **错误现象**：直接使用用户上传的文件名作为云端/本地存储路径，当包含中文、空格、Emoji 或特殊重音符号时，发生路径截断、乱码甚至目录遍历安全隐患。
* **正确规范**：
  1. 存储底层一律使用安全哈希或 UUID（如 `nanoid()` 或 SHA-256）作为物理存储文件名。
  2. 原始文件名只保存在数据库元数据字段中，下载或回读时通过标准 HTTP Header 输出：`Content-Disposition: inline; filename*=UTF-8''<encoded-filename>`。

## 三、数据快照、排期幂等与任务调度规范

### 3.1 零修改保存不得触发新版本与排期失效

* **错误现象**：用户打开稿件编辑页，未做任何修改直接点击“保存”，系统机械式地生成了新的稿件快照版本（Version + 1），并由于版本迭代将原先已排期待发布的任务全部判定为“稿件被修改”而强制暂停。
* **正确规范**：
  保存动作执行前，必须先比对新旧内容的实际指纹（标题、正文、配图哈希列表、视频资产 ID）。若内容完全一致，必须原样返回当前版本，禁止无意义地递增版本号与触动已排期任务。

---

### 3.2 任务排期幂等键（Idempotency Key）设计准则

* **错误现象**：在生成任务幂等键时混入了预定发布时间（`scheduledAt`）。当同一稿件版本在因故改期或重试时，由于时间戳变化生成了新的幂等键，导致同一账号在数据库中生成了多条相互竞争的重复排期任务。
* **正确规范**：
  排期任务的幂等键维度只能锚定在业务实体本身：`workspaceId:manuscriptId:version:accountId`。同一稿件版本在同一账号下只能存在一个活动任务；改期操作应在原任务上更新计划时间，而非插入新记录。

---

### 3.3 账号通道调度串行与租约防超限

* **错误现象**：当多条发布任务在同一时刻到期时，后台 Worker 并发领取并同时向第三方平台调用发文接口，导致平台方报频率超限错误（Rate Limited）或触发风控封禁账号。
* **正确规范**：
  1. 同一发布账号必须严格执行串行派发（同一时间同一账号只允许一条任务处于派发/受理中）。
  2. 任务必须带租约锁机制（Lease Lock），超时未回执的任务需进入「待核实」状态人工复核，严禁暴力重试。

---

### 3.4 稿件内容形态与发布通道的严格校验

* **错误现象**：稿件上传了视频（包含 `videoAssetId`），但在发布排期时未做通道形态校验，直接允许排期给仅支持图文专栏的官方通道，导致任务进入派发阶段后才在调用平台接口时报错。
* **正确规范**：
  在工作台排期接口（调度入口层）进行严格的内容前置类型守卫：官方图文通道检测到视频稿件时，立即抛出明确的业务异常阻断排期，并提示运营人员改用人工交接或切换至支持视频的通道。

---

## 四、开发环境与跨平台命令规范

### 4.1 Windows PowerShell 命令串联语法

* **错误现象**：在 Windows PowerShell 终端中执行 `command1 && command2`，因旧版 PowerShell 不支持 `&&` 语法抛出解析错误：
  `The token '&&' is not a valid statement separator in this version`。
* **正确规范**：
  1. 在跨平台脚本编写或自动化步骤中，命令串联统一使用分号 `;` 分隔：`command1; command2`。
  2. 或在 `package.json` 的 `scripts` 中通过跨平台包（如 `npm-run-all`）或单命令方式执行。
